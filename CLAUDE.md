## 8. How the AI mindmap works

1. **capture.tsx** â€” voice via browser **Web Speech API** (Chrome/Edge), or Type mode. (Claude has no speech-to-text, so transcription is browser-side or typed.)
2. **`structureThought`** server fn (`notio.functions.ts`) â€” sends the transcript to **Claude Haiku 4.5** with a strict JSON schema (`output_config.format`), getting back `{ title, nodes[] }` where each node has label/detail/parentId/priority/category.
3. **`radialLayout`** (`layout.ts`) computes clean, non-overlapping positions; nodes are saved to Supabase.
4. **maps.$id.tsx** renders the interactive mindmap + the to-do list.

Node edits (move/edit/delete/priority/done/color) are done **client-side via the
Supabase SDK** (RLS enforces ownership) for snappiness. **Auto-arrange** recomputes
the radial layout and persists it.

**AI fallback (Session 7):** if Anthropic errors for any reason (rate limit, outage,
key issue), `structureThought` automatically retries once against **OpenRouter,
free models only** (`openrouter.server.ts` â€” tries `openrouter/free`, then
Gemma/Llama/Qwen/Mistral/DeepSeek `:free` variants in order until one responds).
Free models don't get Anthropic's strict `json_schema` tool, so they're given the
exact JSON shape in the prompt text instead and parsed the same way
(`safeParseMap` + Zod). Needs `OPENROUTER_API_KEY` in env â€” if unset, the fallback
is skipped and the original Anthropic error surfaces as-is (unchanged behavior).
**Note:** `ai-generation.server.ts` + `gemini.server.ts` also exist in the repo as
a 3-tier Anthropic â†’ Gemini â†’ OpenRouter chain, but they're dead code (only
`capture.functions.ts` calls them, and nothing routes to `capture.functions.ts`).
`gemini.server.ts` imports `@google/generative-ai`, which **is not an installed
dependency** â€” do not wire captureThought or any new call into that chain without
first running `npm install @google/generative-ai` or it will break the build.
